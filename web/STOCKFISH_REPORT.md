# Локальная интеграционная проверка Stockfish

Среда: Linux x86_64, WSL2, Ubuntu 26.04, Python 3.10, ONNX Runtime 1.20.1,
Stockfish 19 из официальной Linux universal-поставки. RKNN/NPU и conda на
Firefly не проверялись: плата недоступна. TTS в этом этапе отсутствует.

## Что проверено

- `uv sync --locked` и установка `chess==1.11.2` из lock-файла.
- Backend: **20 passed, 1 skipped** с настоящим Stockfish и ONNX YOLOv8m.
  Пропущено переключение всех четырёх моделей: остальные ONNX не экспортированы.
- Проверены легальность истории, произвольный FEN, en passant, превращение,
  повторения, очередь хода, отказ после завершения партии, ограничение сессий.
- API: один поиск, отказ второму запросу, независимость от inference-worker,
  отбрасывание устаревшего ответа, освобождение после ошибки и закрытие движка.
- Проверка YOLO через WebSocket: два свежих совпадения, отказ после первого,
  предупреждений, устаревшего кадра, смены версии и отключения потока.
- Frontend: **3 unit-теста**, TypeScript и production build успешны.
- Chromium: реальная YOLOv8m ONNX распознаёт стартовую расстановку; после двух
  совпадений кнопка запрашивает настоящий Stockfish и получает `e2e4` (`e4`).
  Ответ API маркирован `history_verified_by_yolo`, без подстановки сцены в детектор.
- Chromium: рекомендация не делает ход; выбор другой стороны блокирует кнопку;
  реальный ход мышью e2–e4 синхронизирует историю; подсказка за чёрных работает
  в явно выбранном режиме `history_only`; произвольный FEN с матом блокируется;
  пауза не позволяет использовать старое подтверждение YOLO. Ошибок JavaScript нет.
- Существующая браузерная регрессия: вращение, точный сброс камеры, ходы обеих
  сторон в 3D и ход в 2D — успешно. Генератор датасета: браузерная регрессия успешна.

Для Chromium недостающие libnspr/libnss/libasound скачаны и распакованы только
в `/tmp/opencode`, без изменения системных пакетов. В тестах использован
`LD_LIBRARY_PATH`; это не инструкция установки зависимостей на плату.

## CPU smoke-эксперимент

Для запуска текущей YOLOv8m экспортированы обычный и split ONNX. Численная
проверка PyTorch/ONNX пройдена на **одном** тестовом кадре небольшого
синтетического набора текущей сцены. Это не проверка качества или mAP.
Веса, классы, геометрия и пороги распознавания не менялись.

Воспроизводимый запуск после экспорта из корня:

```bash
STOCKFISH_PATH="$PWD/artifacts/stockfish/x86_64/stockfish" \
web/.venv/bin/python tools/experiment_stockfish.py /path/frame.png --runs 10
```

Настройки: YOLOv8m, 640×640, ONNX CPU, 4 потока; Stockfish 1 секунда,
1 поток, Hash 64 MiB. Оба компонента исполняются, без заглушек.

В одном изолированном коротком проходе:

| Показатель | Результат |
|---|---:|
| Средняя обработка YOLO, 10 кадров без поиска | 325.0 мс |
| Средняя обработка YOLO, 10 кадров с запуском поиска | 404.2 мс |
| Кадры, начатые пока поиск ещё выполнялся | 3 |
| Средняя обработка этих трёх кадров | 457.7 мс |
| Запрос Stockfish | 1006.4 мс, легальный e2e4 |

Полный JSON: локальный `artifacts/stockfish-cpu-experiment.json`.
Сохранённый кадр детектора и стартовая позиция движка в этом нагрузочном
тесте различаются; связанный сценарий проверен отдельно в Chromium.
Разброс WSL/нагрузки и малая выборка не позволяют делать вывод о гарантированном
FPS или скорости Firefly. Оставшиеся семь кадров после завершения поиска нельзя
выдавать за одновременно обработанные кадры; отдельный счётчик приведён выше.

## Поставка Firefly

`artifacts/firefly-stockfish-overlay.tar` — около 173.2 MiB, рядом SHA256.
Проверены ELF ARM64, SHA256 оригинальной поставки, наличие исходников и GPL,
requirements с `chess` и RKNN Lite2, отсутствие Windows EXE/PT/venv/паролей.

**Это обновление существующего YOLO-runtime, не автономная поставка моделей.**
Из-за отсутствия локальных проверенных RKNN в пакет не включены новые или
непроверенные конвертации. Для запуска требуются существующие
`convert/artifacts/chess3d_m` с metadata и RKNN INT8/FP16 с платы.
Упаковщик явно помечает это в `PACKAGE.json`; запуск проверяет наличие файлов.
Установка Python-зависимостей и Stockfish предусмотрена только в отдельную
conda внутри рабочей папки. Инструкция: [STOCKFISH.md](../STOCKFISH.md).

## Известные ограничения

- Плата, ARM64 UCI-запуск, совместимость её ОС/драйверов и нагрузка NPU ещё не проверены.
- У официального ARM64-бинарника есть зависимости GLIBC_2.35. Требуется glibc
  ≥ 2.35; установщик проверяет версию до pip. Для более старой ОС нужна
  сборка из исходников на совместимом окружении, не подмена системной glibc.
- `npm audit`: унаследованная high-уязвимость `source-map-js`
  (GHSA-68fv-2mgg-jv7q); зависимости frontend в этом этапе не обновлялись.
- Сборщик предупреждает о размере JS-бандла; Starlette — об устаревшем алиасе
  AnyIO. Это предупреждения, не падения тестов.
- Сессии не сохраняются на диск; нет аутентификации, публичное размещение не предусмотрено.
