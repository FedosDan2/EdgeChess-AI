# Синтетический датасет из текущего движка

Генератор использует `BoardScene` из web-ui. Сервер инференса и Firefly не нужны.
Нужны Node.js, зависимости frontend и Chromium для Playwright:

```bash
cd web/frontend
npm ci
npx playwright install chromium
npm run dataset
```

В Linux также нужны системные библиотеки Chromium; Playwright перечислит
отсутствующие при запуске (`npx playwright install-deps chromium`). Проверка
перекрытий, восстановления RGB-материалов после масок и порядка углов:
`npm run test:dataset`.

По умолчанию создаётся `data/synthetic-demo` в корне проекта: 24 легальные
шахматные позиции, по два кадра, 640×640, seed 42. Другой набор:

```bash
npm run dataset -- --output ../../data/synthetic-large --positions 1000 --views 4 --size 1024 --seed 123
```

Результат — `data.yaml`, `manifest.json` и `train/val/test`, в каждом
`images/*.png`, `labels/*.txt`, `masks/*.png`, `metadata/*.json`.
Генератор отказывается перезаписывать существующую папку. Незавершённый набор
не содержит итогового `manifest.json`; повторный запуск требует другого output.
Данные исключены из Git.

Варьируются темы wood/marble/walnut, формы classic/slim, yaw 0–360°, pitch
30–80°, расстояние камеры, интенсивность и направление света.
Это существующие процедурные модели и материалы нашего движка, а не ассеты
ChessRender360. Дополнительно можно передать `--glb /path/pieces.glb`:
используется тот же загрузчик, что в UI, с объектами wP/wN/wB/wR/wQ/wK и
bP/bN/bB/bR/bQ/bK. При этом формы classic/slim не используются.

Позиции получаются случайными легальными ходами; начальная включена явно.
Это не выборка реальных партий. Разделение 80/10/10 выполняется по уникальной
позиции, поэтому все её ракурсы и материалы принадлежат одному split.
Для малого набора пропорции округляются; 24 позиции дают 38/4/6 кадров.

## Совместимость с текущей 3D-моделью

YOLO detection: `class cx cy width height`, нормированные координаты,
те же 16 классов и порядок, что у `CV_3D/weights/best_3d_detection.pt`.
Первые 12 — white/black queen, king, bishop, knight, rook, pawn;
12–15 — corner_white_left, corner_white_right, corner_black_left,
corner_black_right. Углы соответствуют a1, h1, h8, a8 и проецируются
по внешней границе игровых клеток; размер corner bbox — 5% стороны изображения,
как 100 пикселей на исходных 2000×2000 в подготовке ChessRender360.

Bbox фигур вычисляются по видимым пикселям отдельного instance-прохода с
depth testing. Все остальные поверхности рендерятся чёрным и участвуют
в перекрытии. Свет, тени, tone mapping и сглаживание в этом проходе выключены.
Границы включают min/max пиксели; YOLO width = xmax − xmin, как в текущем
скрипте подготовки ChessRender360. Полностью невидимые фигуры не размечаются,
их клетки записываются в `hiddenSquares`; частично видимые размечаются.

Маски — RGB PNG: красный канал хранит instance ID, 0 — фон, остальные
каналы равны нулю. Это служебные маски нашего генератора; цветовая кодировка
отличается от ChessRender360. В metadata есть соответствие instance → класс,
клетка, bbox и число видимых пикселей, а также FEN, углы и параметры кадра.

Это небольшой набор для проверки и дообучения на сцене UI. Качество модели
после обучения нужно проверять отдельно, в том числе на исходных данных.
Для переносимого датасета не вписывайте локальный абсолютный путь в data.yaml.

## Проверенный небольшой набор

Создан локально в `data/synthetic-demo`, архив — `artifacts/synthetic-demo.zip`
(данные и архив не входят в Git). Seed 42, 48 изображений 640×640,
24 позиции, 38 train / 4 val / 6 test. В наборе 1206 bbox фигур и 192 bbox
углов. Все bbox фигур проверены по сохранённым маскам, YOLO-координаты — по
metadata; пересечений расстановок между split нет. `validation.json` содержит
результат, `preview.jpg` — девять кадров с наложенной разметкой.
Порядок 16 классов сверён с текущими весами, `data.yaml` успешно открыт
загрузчиком Ultralytics. Обучение модели на этом наборе не запускалось.
